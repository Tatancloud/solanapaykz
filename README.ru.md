# SolanaPay-KZ

[English version](README.md) · [Документация](https://tatancloud.github.io/solanapaykz/ru/)

Открытый набор инструментов, позволяющий интернет-магазину в Казахстане
принимать оплату в стейблкоине **USDC** и в **SOL** на блокчейне Solana,
показывая покупателю цену в **тенге**.

**Деньги идут напрямую с кошелька покупателя на кошелёк продавца.** Ничто в
этом проекте не принимает, не хранит и не может задержать средства продавца.
Приватные ключи не запрашиваются, не создаются и не хранятся — для приёма
платежа достаточно публичного адреса.

---

## Какую задачу это решает

Небольшой магазин в Казахстане, решивший принимать стейблкоины, упирается
сразу в три препятствия:

1. **Нет прямого курса.** Ни одна биржа не котирует криптовалюту к тенге,
   кроме одной пары. Сервисы курсов, которые обычно советуют, тенге не
   поддерживают вовсе — один из них отвечает на запрос успехом и пустым
   объектом, что наивная реализация примет за нулевой курс.
2. **Нет готовой интеграции.** Платформы для магазинов умеют карточные
   шлюзы, а не кошельки.
3. **Посредничество.** Большинство криптоплатёжных сервисов сперва получают
   деньги себе, а рассчитываются потом — именно то, чем небольшой продавец
   рисковать не может.

SolanaPay-KZ отвечает на все три: считает курс по той единственной паре,
которая существует, даёт готовые интеграции для двух платформ и никогда не
прикасается к деньгам.

## Как проходит платёж

```
покупатель                магазин                   Solana
    │                        │                          │
    │   оформляет заказ ──>  │                          │
    │                        │ курс: Binance USDT/KZT   │
    │                        │ сумма заморожена 15 мин  │
    │   <── QR-код / ссылка ─│                          │
    │                                                   │
    │  ────────── платит прямо со своего кошелька ────> │
    │                        │                          │
    │                        │ ── проверяет в сети ──>  │
    │   <── заказ подтверждён│                          │
```

Магазин не держит деньги покупателя, а проект не держит деньги магазина.
Единственное, что код делает с деньгами, — *смотрит* на них.

## Решения, о которых стоит знать

Это выборы, ошибка в которых стоит дороже всего; каждый закреплён тестами:

- **Деньги считаются целыми числами, никогда не дробными.** Суммы переносятся
  строками и вычисляются в минимальных единицах монеты.
- **Округление всегда в пользу продавца**, до последнего знака, который есть
  у монеты: шесть знаков у USDC, девять у SOL.
- **Сбой сети никогда не меняет заказ.** Если узел Solana молчит, заказ
  остаётся как был. Молчание сети не является ответом «денег нет».
- **Несовпадение суммы никогда не разрешается автоматически.** Платёж,
  который найден, но не сходится, передаётся человеку: переводы в блокчейне
  необратимы, и автоматика ошибается здесь дороже.
- **Цена замораживается вместе с заказом** — сумма, получатель, сеть и метка
  платежа — и при проверке не пересчитывается.

## Что где лежит

| Путь | Что это |
|---|---|
| `src/` | библиотека `@solanapaykz/core` на TypeScript |
| `tests/` | её тесты |
| `tilda-server/` | платёжный сервер для магазинов на Tilda (TypeScript, Node 22) |
| `demo-shop/plugin/` | плагин WooCommerce (PHP 8.1) |
| `demo-shop/` | демо-магазин в Docker |
| `docs/` | публичный сайт документации (GitHub Pages) |
| `process/` | как это делалось: ТЗ, спецификации, планы, карта кода |

Папка `process/` для репозитория необычна и оставлена намеренно: в ней лежат
проектные решения, планы работ и находки ревью, из которых вырос код. Тот,
кто оценивает инженерную часть, может прочитать рассуждения, а не только
результат.

## Что понадобится

- **Собственный узел Solana.** Публичные ограничивают частоту запросов и не
  хранят достаточно истории, чтобы надёжно найти платёж. Это обязательное
  требование, а не пожелание.
- PHP 8.1 с расширением `bcmath` для плагина WooCommerce.
- Node.js 22 для библиотеки и сервера Tilda.
- Валюта магазина — тенге.
