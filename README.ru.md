## Проблема и решение

Небольшой магазин в Казахстане, решивший принимать стейблкоины, упирается сразу в три препятствия.

### 1. Нет прямого курса
- **Проблема:** ни одна биржа не котирует криптовалюту к тенге, кроме одной пары. Сервисы курсов, которые обычно
  советуют, тенге не поддерживают вовсе — один из них отвечает на запрос успехом и пустым объектом, что наивная
  реализация примет за нулевой курс.
- **SolanaPay-KZ:** считает курс SOL/KZT и USDC/KZT по Binance (USDT/KZT × SOL/USDT или USDC/USDT) и замораживает
  сумму вместе с заказом на 15 минут.

### 2. Нет готовой интеграции
- **Проблема:** платформы для магазинов умеют карточные шлюзы, а не кошельки, — а многие продавцы вообще без сайта
  и продают в WhatsApp, Instagram или Telegram.
- **SolanaPay-KZ:** готовые интеграции для WooCommerce и Tilda, SDK на TypeScript для всех остальных и **платёжные
  ссылки** в тенге, которые продавец вставляет в любой чат.

### 3. Посредничество
- **Проблема:** большинство криптоплатёжных сервисов сперва получают деньги себе, а рассчитываются потом — именно то,
  чем небольшой продавец рисковать не может.
- **SolanaPay-KZ:** никогда не прикасается к деньгам. Покупатель платит на собственный кошелёк продавца; комиссия
  сервиса 0,5% берётся внутри той же транзакции. Единственное, что код делает с деньгами, — *смотрит* на них.

## Почему Solana

- **Solana Pay** — открытый стандарт платёжных запросов и QR-кодов: ссылку оплатит любой кошелёк Solana (Phantom,
  Solflare, Backpack) без отдельного приложения
- **Transaction request** — сервер сам собирает транзакцию, поэтому оплата продавцу и комиссия 0,5% приходят вместе,
  одним переводом
- **Blinks (Solana Actions)** — та же платёжная ссылка разворачивается в кнопку оплаты прямо в X
- **USDC** — долларовый стейблкоин в самой сети, поэтому цена в тенге не зависит от колебаний криптовалют
- **Скорость и цена** — платёж подтверждается за секунды и стоит доли цента, поэтому выгодны даже небольшие заказы
  из чата

## Возможности

- Платёжные ссылки в тенге для чатов с оплатой в USDC или SOL — в одно касание из кошелька, по QR или через Blink в X
- Ручная оплата с любого кошелька или биржи, платёж распознаётся по уникальной сумме
- Комиссия 0,5% делится в самой транзакции; при ручной оплате записывается долгом и гасится из кабинета
- Аккаунты продавцов со входом по email или кошельком, кабинет, выгрузка в CSV и уведомления на почту
- Telegram-бот для продавцов
- Плагин WooCommerce и платёжный сервер для магазинов на Tilda
- SDK `@solanapaykz/core`: котировка, платёжный запрос и проверка — для Node.js 20.18+ и браузера
- Интерфейс на русском и английском

## Архитектура

```
покупатель                магазин                   Solana
    │                        │                          │
    │   оформляет заказ ──>  │                          │
    │                        │ курс: Binance SOL/KZT    │
    │                        │ (USDT/KZT × SOL/USDT)    │
    │                        │ сумма заморожена 15 мин  │
    │   <── QR-код / ссылка ─│                          │
    │                                                   │
    │  ────────── платит прямо со своего кошелька ────> │
    │                        │                          │
    │                        │ ── проверяет в сети ──>  │
    │   <── заказ подтверждён│                          │
```

Магазин не держит деньги покупателя, а проект не держит деньги магазина.

**Платёжные ссылки для чатов.** Продавец, который торгует в WhatsApp, Instagram или Telegram, создаёт платёжную
ссылку с ценой в тенге и вставляет её в чат. Покупатель платит USDC или SOL в одно касание (transaction request
Solana Pay), ручным переводом с любого кошелька или биржи либо через Blink. Деньги идут прямо на кошелёк продавца;
сервис берёт 0,5% внутри той же транзакции и никогда не хранит ни средства, ни ключи. Подробнее —
[docs/links.md](docs/links.md).

### Решения, о которых стоит знать

Это выборы, ошибка в которых стоит дороже всего; каждый закреплён тестами:

- **Деньги считаются целыми числами, никогда не дробными.** Суммы переносятся строками и вычисляются в минимальных
  единицах монеты.
- **Округление всегда в пользу продавца**, до последнего знака, который есть у монеты: шесть знаков у USDC, девять
  у SOL.
- **Сбой сети никогда не меняет заказ.** Если узел Solana молчит, заказ остаётся как был. Молчание сети не является
  ответом «денег нет».
- **Несовпадение суммы никогда не разрешается автоматически.** Платёж, который найден, но не сходится, передаётся
  человеку: переводы в блокчейне необратимы, и автоматика ошибается здесь дороже.
- **Цена замораживается вместе с заказом** — сумма, получатель, сеть и метка платежа — и при проверке не
  пересчитывается.

## Быстрый старт

**Понадобится:** Node.js 22 и npm; PHP 8.1 с `bcmath` для плагина WooCommerce; собственный узел Solana (RPC).

```bash
# Клонировать репозиторий
git clone https://github.com/Tatancloud/solanapaykz
cd solanapaykz

# SDK: установка, тесты, сборка
npm install
npm test
npm run build

# Сервер для Tilda и платёжные ссылки
cd tilda-server
npm install
npm test
cp config.example.json config.json   # указать RPC, кошельки и SMTP
npm run build && npm start
```

Запуск сервера в Docker: [`tilda-server/docker-compose.yml`](tilda-server/docker-compose.yml) · Инструкция для Tilda:
[документация](https://tatancloud.github.io/solanapaykz/ru/tilda) · Плагин WooCommerce: [`demo-shop/plugin/`](demo-shop/plugin/).

### Что понадобится

- **Собственный узел Solana.** Публичные ограничивают частоту запросов и не хранят достаточно истории, чтобы надёжно
  найти платёж. Это обязательное требование, а не пожелание.
- PHP 8.1 с расширением `bcmath` для плагина WooCommerce.
- Node.js 22 для библиотеки и сервера Tilda.
- Валюта магазина — тенге.

## Что где лежит

| Путь | Что это |
|---|---|
| `src/` | библиотека `@solanapaykz/core` на TypeScript |
| `tests/` | её тесты |
| `tilda-server/` | платёжный сервер для магазинов на Tilda и сервис платёжных ссылок (TypeScript, Node 22) |
| `demo-shop/plugin/` | плагин WooCommerce (PHP 8.1) |
| `demo-shop/` | демо-магазин в Docker |
| `docs/` | публичный сайт документации (GitHub Pages) |
| `process/` | как это делалось: ТЗ, спецификации, планы, карта кода |
| `assets/` | логотип и постер |

Папка `process/` для репозитория необычна и оставлена намеренно: в ней лежат проектные решения, планы работ и находки
ревью, из которых вырос код. Тот, кто оценивает инженерную часть, может прочитать рассуждения, а не только результат.
