**Тема:** Универсальная платежная система: прошу добавить шаблон «Оплата криптовалютой (USDC на Solana)» в общий список

Здравствуйте.

Мы настроили универсальную платежную систему в проекте 10868059 по варианту
«Новая платежная система (для разработчиков)», провели тестовый платеж, и он
проходит. Просим проверить шаблон и добавить его в общий список платежных
систем, чтобы им могли пользоваться другие магазины на Tilda.

**Что это за платежная система.** Приём оплаты в криптовалюте (USDC и SOL в
сети Solana) с ценой в тенге и пересчётом по курсу на момент заказа. Решение с
открытым исходным кодом, сделано для казахстанских магазинов; кроме интеграции
с Tilda в нём есть плагин для WooCommerce и библиотека для своих сайтов.

- Исходный код: https://github.com/Tatancloud/solanapaykz
- Документация: https://tatancloud.github.io/solanapaykz/
- Демо-магазин на Tilda: https://kzwedding.tilda.ws/solanapay
- Демо-магазин на WooCommerce: https://shop.pagafox.kz

**Настройки в кабинете:**

- ID платежной системы: 3061174
- Логин: solanapaykz
- Валюта: KZT, страна KZ
- API URL и тестовый API URL: https://pay.kabyldau.digital/tilda/pay
- URL для уведомлений: https://forms.tildaapi.pro/payment/custom/ps3061174
- Подпись заказа: HMAC-SHA-256, секрет как ключ алгоритма, шаблон
  `order|{{order_id}}|{{amount}}|{{currency}}|{{timestamp}}|{{test_mode}}`
- Подпись уведомления: то же, но с меткой `notify` вместо `order` и отдельным
  секретом
- Признак успешной оплаты в уведомлении: `status` = `paid`
- Ответы на уведомление: `OK` / `ERROR`

**Особенность, о которой стоит знать заранее:** у каждого магазина свой
собственный сервер приёма оплаты и свой адрес «API URL» — деньги идут напрямую
на кошелёк магазина, посредника между магазином и покупателем нет. Поэтому в
шаблоне адрес API не может быть общим для всех: его заполняет сам магазин, как
логин и секрет. Если это мешает публикации шаблона в общем списке, подскажите,
пожалуйста, как принято оформлять такие интеграции.
