# Универсальная платёжная система Tilda — протокол

Собрано 10 сентября 2026 из личного кабинета Tilda (тариф Personal), раздел
«Настройки сайта → Платежные системы → Универсальная платежная система →
Новая платежная система (для разработчиков)». В публичной документации этих
подробностей нет: русская и английская справка описывают только экран
настроек, а имена параметров называют «списком соответствия полей», не
раскрывая его.

Проверять по этому файлу, а не по справке.

## Что это

В списке платёжных систем Tilda около 57 готовых шаблонов (Fondy,
FreedomPay KZ, ePay Halyk, Prodamus KZ и другие) плюс пункт **«Новая
платежная система (для разработчиков)»**. Он открывает форму создания
собственной интеграции.

Справка противоречит сама себе в вопросе модерации: в одном месте сказано,
что шаблон становится доступен проекту только после одобрения, в другом —
что сначала надо провести тестовый платёж, а к модераторам обращаться, чтобы
шаблон стал доступен **остальным** пользователям. В форме есть отдельное поле
«Тестовый API URL» и галочка «Отключить тестовый режим», что говорит в пользу
второго прочтения. Выяснится подачей заявки.

## Порядок обмена

1. Покупатель нажимает «Оформить заказ» в корзине Tilda.
2. Tilda сохраняет заказ у себя и формирует набор параметров по «списку
   соответствия полей» интеграции.
3. Покупателя перенаправляют **POST-запросом** на наш «API URL». Среди
   параметров обязательно поле подписи.
4. Мы проверяем подпись, показываем страницу оплаты, принимаем платёж.
5. Мы шлём **POST на «URL для уведомлений»** Tilda: номер заказа, сумму,
   признак оплаты и подпись.
6. Заказ помечается оплаченным **только** при верной подписи, верном номере
   заказа, верной сумме и признаке оплаты.

## Настройки интеграции

Адреса и режим:

| Поле | Назначение |
|---|---|
| `payments[json][apiurl]` | боевой адрес, куда перенаправляется покупатель |
| `payments[json][testapiurl]` | адрес для тестовых платежей |
| `payments[testmodeoff]` | галочка «Отключить тестовый режим» |
| `payments[successurl]`, `payments[failureurl]` | страницы успеха и отказа |
| `payments[currency]` | валюта; **KZT в списке есть** |
| `payments[accountid]` | логин продавца в платёжной системе |
| `payments[json][secret]` | секрет для подписи заказа |
| `payments[json][notifysecret]` | отдельный секрет для уведомлений, если нужен |

## Соответствие полей

Имена параметров задаём мы. Для каждого поля указывается имя, у некоторых —
формат:

| Наше поле | Форматы |
|---|---|
| `login` | — |
| `currency` | `RUB/USD/...` или числовой код `643/840/...` |
| `lang`, `country` | верхний или нижний регистр |
| `successurl`, `failureurl`, `notifyurl` | — |
| `testmode` | `1/0` или `true/false` |
| `number` (номер заказа) | `<ID проекта>:<ID заказа>` или `<ID проекта>_<ID заказа>` |
| `desc` | плюс максимальная длина |
| `amount` | в рублях/долларах или в копейках/центах |
| `timestamp` | ISO-8601 или Unix-время |
| `email`, `phone`, `name` | у имени — «Имя» или «ФИО» |
| `signature` | — |
| `products` | массив в JSON или JSON в base64 |
| `receipt` | массив в JSON или JSON в base64 |

Элементы товара внутри `products`: `number` (нумерация с единицы или с нуля),
`name` (плюс максимальная длина), `quantity`, `price`, `amount`, `image`.
Отдельные галочки: добавлять доставку в список товаров, использовать цену со
скидкой.

## Подпись

Настраивается отдельно для заказа и для уведомления (у уведомления есть
галочка «использовать те же правила»):

- **Тип:** «Все поля» либо «Особые правила».
- **Особые правила** — строка вида
  `{{secret}}|{{amount}}|{{currency}}|{{merchant_id}}|{{order_desc}}|{{order_id}}|{{version}}`.
- Исключать поля с пустыми значениями — галочка.
- Порядок полей: по алфавиту с начала или с конца.
- Разделитель значений — произвольная строка.
- Секрет: не добавлять, первым элементом или последним.
- Алгоритм: MD5, SHA-1, SHA-256, SHA-384, SHA-512.
- Секрет как ключ алгоритма (HMAC) — галочка.
- Привести к верхнему регистру — галочка.
- Итоговую подпись в base64 — галочка.

## Ответ на уведомление

| Поле | Назначение |
|---|---|
| `answer[success][field]`, `answer[success][value]` | имя и значение признака успешной оплаты |
| `answer[transaction][field]` | номер транзакции; формат целое число, UUID или произвольный |
| `answer[message][success]` | что Tilda получит в ответ при успехе (по умолчанию `OK`) |
| `answer[message][error]` | что при ошибке (по умолчанию `ERROR`) |
| `answer[message][json]` | галочка: отвечать в формате JSON |

## Тексты для продавца

Названия и подсказки полей настраиваются на русском и английском
(`skin[...][label][RU|EN]`, `skin[...][hint][RU|EN]`), включая адрес
поддержки, ссылку обратной связи и ссылку на справку.

## Что из этого следует для нас

- Протокол полностью в наших руках: имена параметров, правила подписи и
  формат ответа выбираем мы.
- Подпись стоит делать HMAC-SHA-256 — он есть в списке, и это единственный
  вариант, где секрет участвует как ключ, а не как склеенная строка.
- Сумма приходит от Tilda, а не из браузера покупателя. Это важно: сумму
  нельзя брать с клиента ни при каких условиях.
- Номер заказа приходит в виде `<ID проекта>:<ID заказа>` — он уникален в
  пределах Tilda, и его можно использовать как ключ заказа у нас.
