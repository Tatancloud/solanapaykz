## 1. Название

**SolanaPay-KZ**

## 2. Цель

Open-source SDK и готовые плагины для CMS Tilda и WooCommerce, позволяющие
малому и среднему бизнесу в Казахстане принимать платежи в криптовалюте
(USDC/SOL) с автоматической конвертацией из тенге по актуальному курсу.

## 3. Проблема

Приём международных платежей для предпринимателей и фрилансеров в Казахстане
связан с высокими комиссиями, задержками и риском блокировок. На Tilda и
WordPress (WooCommerce) нет простого готового решения для приёма стейблкоинов
на блокчейне Solana без посредников и сложных интеграций.

## 4. Решение

Две ключевые части:

1. **Core SDK** — библиотека, инкапсулирующая логику конвертации KZT в USDC/SOL
   и генерацию QR-кода для оплаты через Solana Pay.
2. **Готовые интеграции** — плагины и скрипты для подключения к сайтам на
   WooCommerce и Tilda.

Процесс для конечных пользователей: продавец получает USDC напрямую на свой
кошелёк (например, Phantom) с минимальной комиссией, покупатель оплачивает
товар, отсканировав QR-код мобильным кошельком.

## 5. Компоненты и архитектура

### 5.1. Core SDK (JS/TS)

Ядро системы в виде JS/TS модуля.

**Функционал:**

- принимает на вход сумму в KZT;
- запрашивает актуальный курс KZT/USDC через API биржи, с механизмом
  fallback на резервный источник при отказе основного;
- конвертирует сумму из KZT в USDC;
- генерирует QR-код по спецификации Solana Pay, включающий адрес получателя,
  сумму и другие необходимые параметры.

**Требования:**

- код опубликован в открытом репозитории на GitHub;
- библиотека хорошо документирована для сторонних разработчиков.

### 5.2. Плагин для WooCommerce

- интеграция в качестве нового платёжного шлюза;
- страница настроек в админ-панели WordPress, где продавец указывает свой
  Solana-адрес для приёма платежей;
- на странице оформления заказа при выборе способа оплаты вызывается Core SDK
  для генерации и отображения QR-кода с нужной суммой;
- механизм проверки статуса транзакции в сети Solana для подтверждения оплаты;
- уровень подтверждения (commitment level) — `finalized`, чтобы исключить риск
  отката транзакции.

### 5.3. Интеграция с Tilda

- виджет или скрипт для встраивания на сайт Tilda;
- работа через кастомные платёжные шлюзы Tilda или механизм Webhooks;
- детальная инструкция для пользователей Tilda, не являющихся разработчиками.

### 5.4. Требования к безопасности

Плагины и SDK **ни при каких обстоятельствах** не запрашивают, не хранят и не
обрабатывают приватные ключи пользователей. Вся работа с кошельками происходит
на стороне клиента (в браузере) по стандартам Solana Wallet Adapter.

## 10. Уточнения к ТЗ

Проверено на практике 7 сентября 2026. Решения согласованы с заказчиком.

### 10.1. Источник курса: CoinGecko не поддерживает тенге

ТЗ рекомендует CoinGecko как основной источник курса, предполагая наличие
прямого тикера для KZT. **Это не так.**

Проверка `GET /api/v3/simple/supported_vs_currencies` возвращает 63 валюты,
`kzt` среди них отсутствует (есть `rub`, `try`, `uah`). Запрос цены в `kzt`
отвечает HTTP 200 и пустыми объектами — отказ происходит молча:

```json
{"usd-coin":{},"solana":{}}
```

**Решение — приоритет источников развёрнут:**

| Приоритет | Источник | Значение на момент проверки |
|---|---|---|
| Основной | Binance `USDTKZT` | 459.60 ₸ (bid 459.40 / ask 459.50, спред 0.02%) |
| Резервный | синтетика: USD/KZT × USDC/USD | ~455.30 ₸ |

На Binance существует ровно одна пара с тенге — `USDTKZT`; оборот 15.5 млн ₸
и ~1500 сделок в сутки. Пар `KZTUSDC` или `BTCKZT` не существует.

Для резервной синтетики: USD/KZT берётся у Нацбанка РК
(`nationalbank.kz/rss/get_rates.cfm?fdate=DD.MM.YYYY`, XML) или `open.er-api.com`,
USDC/USD — у CoinGecko. Курс Binance выше официального примерно на 0.9% —
это нормальная крипто-премия, её несёт продавец.

Пустой ответ CoinGecko считается ошибкой источника и приводит к переключению
на фолбэк, а не принимается за нулевой курс.

### 10.2. Версии: `@solana/pay` несовместим с `@solana/kit` 8

ТЗ рекомендует `@solana/kit`. Актуальная версия — 8.2.0 (29 августа 2026),
но `@solana/pay@1.0.26` требует `@solana/kit@^6.4.0`. Совместная установка
падает:

```
npm error peer @solana/kit@"^6.4.0" from @solana-program/memo@0.11.2
npm error   peer @solana-program/memo@"^0.11.0" from @solana/pay@1.0.26
npm error Could not resolve dependency
```

Связка `@solana/pay@1.0.26` + `@solana/kit@6.10.0` устанавливается чисто:
72 пакета, 0 уязвимостей.

**Решение:** используем `@solana/pay@1.0.26` с закреплённым `@solana/kit@6.10`.
Требование ТЗ соблюдено — `@solana/pay` уже построен на архитектуре kit.
Готовые `findReference` и `validateTransfer` предпочтительнее самописных:
ошибка в проверке входящего платежа означает принятый чужой или заниженный
перевод. Переход на kit 8 — после того, как `@solana/pay` его поддержит;
SDK изолирует эту зависимость внутри себя.

### 10.3. Параметры риска

QR-код Solana Pay содержит фиксированную сумму в USDC, поэтому курс
замораживается в момент генерации, а платит покупатель когда захочет.

Замеренная волатильность `USDTKZT` за сутки (288 пятиминутных свечей):
диапазон 457.30–461.50 ₸ (размах 0.92%); колебание внутри 5 минут —
медиана 0.000%, 95-й перцентиль 0.065%, максимум 0.503%.

**Решение:**

- срок жизни котировки — **15 минут**; по истечении QR помечается просроченным
  и сумма пересчитывается по свежему курсу;
- наценка продавца — параметр конфигурации, **по умолчанию 0**;
- округление суммы USDC — до 6 знаков вверх, в пользу продавца.

### 10.4. RPC-адрес

Публичный `api.mainnet-beta.solana.com` жёстко лимитирован и непригоден для
продакшена. RPC-адрес не зашивается в код, а передаётся параметром
конфигурации: devnet при разработке, собственный провайдер продавца в проде.
