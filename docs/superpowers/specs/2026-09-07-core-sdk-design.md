## 1. Что делает SDK

Библиотека на TypeScript, которая превращает сумму в тенге в платёжный
запрос Solana Pay и умеет проверить, что платёж действительно пришёл.

Три операции, всё остальное — детали:

1. **Котировка** — сколько USDC (или SOL) соответствует N тенге прямо сейчас.
2. **Платёжный запрос** — URL и QR-код по спецификации Solana Pay.
3. **Проверка** — нашлась ли в блокчейне транзакция по этому запросу и
   верна ли она.

## 2. Границы

**Входит:** конвертация курса, генерация Solana Pay URL и QR, поиск и
валидация транзакции.

**Не входит:**

- хранение заказов и котировок — SDK не имеет состояния между вызовами;
- любая работа с приватными ключами (запрет из ТЗ, п. 5.4);
- отправка транзакций — платит покупатель своим кошельком;
- UI — им занимаются плагины этапов 2 и 3.

Причина отсутствия состояния: WooCommerce хранит заказы в своей базе, Tilda —
в своей. Собственное хранилище SDK стало бы вторым источником правды и
рассинхронизировалось бы с ними.

## 3. Архитектура

```
src/
  index.ts          публичный API
  config.ts         конфигурация, адреса токенов по кластерам
  errors.ts         типы ошибок
  rates/
    types.ts        интерфейс RateSource
    binance.ts      основной источник
    synthetic.ts    резервный источник
    provider.ts     фолбэк и кеш
  quote/quote.ts    котировка, срок жизни, округление
  payment/request.ts   Solana Pay URL, reference, QR
  verify/verify.ts     поиск и валидация транзакции
```

Модули знают только о слое ниже: `quote` не знает про блокчейн, `payment` не
знает, откуда взялся курс, `verify` работает с уже готовой котировкой.

### 3.1. Слой курса

Интерфейс с двумя реализациями:

```ts
interface RateSource {
  readonly name: string;
  getKztPerToken(token: 'USDC' | 'SOL'): Promise<number>;
}
```

**BinanceRateSource** (основной) — `GET /api/v3/ticker/price`:

- USDC: `USDTKZT` × `USDCUSDT` (второй множитель ≈ 1.0, но берётся фактический);
- SOL: `USDTKZT` × `SOLUSDT`.

**SyntheticRateSource** (резервный) — USD/KZT от `open.er-api.com` (при отказе —
XML Нацбанка РК) × цена токена в USD от CoinGecko.

**RateProvider** — оркестратор: пробует основной, при ошибке переходит к
резервному, кеширует результат на время жизни котировки.

Критично: **пустой ответ считается ошибкой.** CoinGecko на запрос цены в KZT
отвечает HTTP 200 и `{"usd-coin":{}}` — молчаливый отказ. Нулевой или
отсутствующий курс обязан приводить к переключению источника, а не к нулевой
сумме к оплате. Это же правило применяется к любому источнику: курс должен
быть конечным положительным числом, иначе источник считается упавшим.

Если упали оба источника — `RateUnavailableError`. SDK не подставляет
последний известный курс: устаревший курс хуже явной ошибки, потому что
продавец получит деньги по неизвестно какой цене.

### 3.2. Котировка

```ts
interface Quote {
  quoteId: string;        // uuid, для связи с заказом на стороне продавца
  amountKzt: number;
  token: 'USDC' | 'SOL';
  amountToken: string;    // строка, не число — см. ниже
  rate: number;           // тенге за токен, уже с наценкой
  rateSource: string;     // 'binance' | 'synthetic', для аудита
  createdAt: string;
  expiresAt: string;
}
```

Срок жизни — **15 минут** от создания. Основание: замер волатильности
`USDTKZT` за сутки — колебание внутри 5 минут медиана 0.000%, 95-й перцентиль
0.065%, максимум 0.503%; суточный размах 0.92%.

Наценка продавца — множитель к курсу, по умолчанию 0.

Округление — до 6 знаков (decimals USDC) **вверх**, в пользу продавца.

`amountToken` хранится строкой. Причина: `number` в JavaScript — double, и
сумма денег в нём округляется незаметно для глаза. Расчёт ведётся в целых
минимальных единицах токена (для USDC — 1e-6), наружу отдаётся строка.

### 3.3. Платёжный запрос

```ts
interface PaymentRequest {
  quote: Quote;
  url: string;            // solana:<recipient>?amount=...&spl-token=...&reference=...
  reference: string;      // публичный ключ-метка
  qr: string;             // SVG
}
```

`reference` — случайный публичный ключ, по которому потом ищется транзакция.
Он не участвует в переводе средств, только помечает её. **Вызывающая сторона
обязана сохранить `reference` вместе с заказом** — без него платёж невозможно
сопоставить с заказом. Это единственное требование SDK к хранилищу продавца.

URL и QR строятся через `@solana/pay` (`encodeURL`, `createQR`).

### 3.4. Проверка платежа

```ts
type PaymentStatus =
  | { status: 'pending' }
  | { status: 'confirmed'; signature: string; amountPaid: string }
  | { status: 'expired' }         // срок котировки истёк, платёж не найден
  | { status: 'mismatch'; signature: string; reason: string };
```

Порядок: `findReference` ищет транзакцию по метке → `validateTransfer`
проверяет получателя, сумму, токен и reference. Обе функции берутся из
`@solana/pay`, а не пишутся самостоятельно: ошибка в этой проверке означает
принятый чужой или заниженный платёж.

Уровень подтверждения — `finalized` (требование ТЗ, п. 5.2), чтобы исключить
откат транзакции.

**Просроченная котировка и пришедший платёж.** Если срок истёк, а деньги
всё же поступили — SDK возвращает `confirmed` с фактической суммой, а не
отменяет платёж: транзакция в блокчейне необратима, отменить её SDK не может.
Решение (принять, доплатить, вернуть) принимает продавец на уровне плагина.
Статус `expired` означает ровно одно: срок вышел и платежа не найдено.

## 4. Публичный API

```ts
const sdk = new SolanaPayKZ({
  recipient: 'адрес продавца',
  rpcUrl: 'https://...',
  cluster: 'mainnet' | 'devnet',
  markupPercent: 0,
  quoteTtlMs: 15 * 60 * 1000,
});

const quote   = await sdk.createQuote({ amountKzt: 10000, token: 'USDC' });
const request = await sdk.createPaymentRequest(quote, { label: 'Магазин', message: 'Заказ №123' });
const status  = await sdk.checkPayment({ reference: request.reference, quote });
```

Адрес RPC — обязательный параметр без значения по умолчанию. Публичный
`api.mainnet-beta.solana.com` жёстко лимитирован и не хранит достаточной
истории для `findReference`; молчаливая подстановка нерабочего адреса по
умолчанию привела бы к отказам проверки уже в проде.

Адреса USDC (проверены запросом `getTokenSupply`):

| Кластер | Mint | Decimals |
|---|---|---|
| mainnet | `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` | 6 |
| devnet | `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU` | 6 |

## 5. Ошибки

Типизированные классы, каждый с полем `cause`:

- `RateUnavailableError` — оба источника курса недоступны;
- `QuoteExpiredError` — попытка создать платёжный запрос по истёкшей котировке;
- `ConfigError` — неверный адрес получателя, отсутствует RPC;
- `PaymentValidationError` — транзакция найдена, но не проходит проверку.

Сетевые таймауты: 10 секунд на источник курса, чтобы отказ одного не подвесил
оформление заказа.

## 6. Тестирование

Разработка по TDD: тест до реализации.

Юнит-тесты (vitest) на зафиксированных ответах API:

- конвертация и округление вверх, включая суммы с длинным хвостом;
- наценка 0 и ненулевая;
- истечение котировки на границе 15 минут;
- **фолбэк**: основной источник вернул ошибку — взят резервный;
- **молчаливый отказ**: CoinGecko вернул `{}` — источник признан упавшим;
- нулевой и отрицательный курс отвергается;
- оба источника упали — `RateUnavailableError`;
- формирование Solana Pay URL с корректными параметрами.

Интеграционные тесты на devnet — отдельным набором, не в основном прогоне
(зависят от сети).

## 8. Структура репозитория

SDK живёт в корне репозитория (`src/`, `package.json`), плагины следующих
этапов лягут рядом в `woocommerce/` и `tilda/`. Монорепо с workspaces не
вводится: один публикуемый npm-пакет не оправдывает лишнего слоя, а `files`
в `package.json` не даст PHP-коду попасть в публикацию.
